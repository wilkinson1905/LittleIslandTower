# 詳細設計：Little Island Tower

## 構成
`dollhouse-maker` のエンジンを流用する。`src/*.js` をつなげて `dollhouse.html` にする。

- `00_core.js`：描画の基本と光の焼き込み。階数に応じて物体を選んで焼き直す
- `10_tower.js`：塔、屋根、小塔、空と海
- `11_floor1.js`、`12_floor2.js`、`13_floor3.js`：各階の部屋
- `14_island.js`：島の地面と飾り
- `20_sprites.js`：動物と小物のスプライト
- `30_timeline.js`：動物のストーリー
- `40_fx.js`：動く要素
- `45_game.js`：育成の状態、操作、画面、セーブ
- `50_main.js`：描画ループ

## 主要な判断
- 塔の平面は画面上で幅140、奥行き70の六角形、階の高さは100。正面を切り開き、奥の3面の壁を見せる。屋根は壁に直接のるベル形で、階が増えると一番上へ移る
- 六角形の壁は箱の前後関係で並べられないので、描く順番を階ごとの層で決める
- 物体に `level`（その階数以上で出す）と `only`（その階数のときだけ出す）を持たせ、階が増えるときに焼き直す。切り替えは雲で隠す
- 背景の動きは時刻と進行状況だけで決まる。育成の状態は別に持ち、ループの検証は進行を固定して行う
- 物体に `furn`（買ったら出す）を持たせ、買ったときに焼き直す。各階の寝床は `furn` を持たないので最初からある
- 動物の予定はブロックの開始時に階数と家具を読んで作る。家具を買っても再生中のブロックは変えず、次のブロックから使う。動物が瞬間移動しないようにするため
- カニの反応は動物の予定から読むので、絵は時刻と進行状況だけで決まるまま
- 動物の予定はブロックの開始時に「誰がいるか」も読み、相手がいれば交流、いなければ一人の行動にする。誰がいるかが変わるのは塔が伸びたときと、留守のあとに新しいペットが来たときだけなので、再生中のブロックが不自然に変わらない
- 雨の日の行動はブロックのシードで決める（外に残るか、雨のあとに窓辺へ行くか外へ行くか）。同じシードなら同じ行動になり、ループの検証が保たれる
- 風船は開いている間だけ `advance()` で進むゲームの要素で、検証用の全部入りの絵には出ない
- カタログの絵は、その家具の物体だけを部屋と同じ描画処理で描いて切り抜く。風鈴、モビール、ランタン、金魚ばちの一部は動く層にしかないので、動く層の描画を取り込む
- 強調表示はフレームの合成後に、輪郭だけを光らせる。画面は暗くしない。終わったら買う前のカメラに戻す。その間にプレイヤーが別の階を選んでいたら、そのままにする

## 空腹

- ゲージは `GS.hunger`。`WORLD.hunger` で絵に渡す。全部入りの検証の絵では常に満腹なので、ループの一致は保たれる
- ストーリーの途中で動物が瞬間移動しないよう、段階（0普通、1家にいる、2寝る）はブロックが変わるときだけ `BLOCK_TIER` に写す。`blockFor` のキーにも入れる
- 段階が0でない動物は、`compileBlock` でストーリーの代わりに家の中だけの予定（`hungryRest`）を使う
- 交流の相手の確認は `present` ではなく `avail`（いて、段階が0）を使う
- 寝ている間におやつをもらうと、ブロックの残りは眠りの姿勢を起きた姿勢に置き換えて家で待つ

## バックグラウンドからの復帰

Android のブラウザは、隠れている間にキャンバスの中身を捨てることがある。毎フレーム描く層は平気で、焼き込んだ層（空、雲、塔と島）だけ消えるので、症状と合う。

- 隠れた時間が10秒以上なら `restorePicture`（空と塔を焼き直し、画面サイズを計算し直し、アイコンを描き直す）。10秒未満でも絵を調べて壊れていれば同じことをする
- `pictureOk` は、焼き込んだ色と実際の層の色を数十点で比べる
- 直らなければ1秒後にもう一度試し、だめなら「再読み込み」ボタンを出す
- キャンバスの `contextrestored`、ページの `pageshow`（保存された状態から）、`resume` でも同じ処理をする

## 犬と猫の向き

- 犬と猫の歩き、立ち、伸び、ジャンプは真横の絵で描く。右向きの絵を1組持ち、左へ進むときは左右反転する
- 体を斜めに歪める `shear` は犬と猫には使わない
- 画面の縦方向へ進む区間（横の移動量の0.75倍より縦の移動量が大きい）は、手前へは `walkFront`、奥へは `walkBack` で歩く。床の軸に沿った移動は横向きのまま
- はしごは `walkBack`、窓辺は後ろ姿（`K.back`、`D.back`）を使う

## タップの反応

- `WORLD.tap[key]` に開始時刻を入れ、各 `fx` が `tapAge` で読む。終わると自分で消す。何もタップしなければ絵は時刻だけで決まるまま
- 位置は各 `fx` が描くときに `CRIT` へ記録し、当たり判定で読む。海の上のものは海が見えている所、空のものは屋外の所でだけ当たる
- タップは `click` で受ける。`pointerup` で受けると、開いたカードが指の下に来て、続く `click` がカードのボタンを押してしまう
- 亀は桟橋に隠れない高さ（y=574）を泳ぐ
- シーグラスの抽選はタップのときに `Math.random` で行う。絵には関わらないので、ループの検証に影響しない

## 計測

`tools/analytics.mjs` の `withAnalytics` が、公開時だけ `window.__analytics` を差し込む。ゲームはこれがあるときだけ同意を聞く。Google の URL は開発用の `dollhouse.html` に入らないので、外部参照なしの検証は変わらない。同意は保存データとは別のキーに持ち、やり直しでは消さない。

## テスト
- `tools/verify.mjs`：スキルの完了条件。全部入りの状態で調べる
- `tools/game_test.mjs`：セーブと再開、留守の分、最初から完成までの通し

## 決まった数値

自動テストの模擬プレイで調整した値。実機で遊んだ感想で変える可能性がある。

- シーグラス：10秒ごとに1個、浜に最大12個。青1（72%）、緑2（23%）、琥珀5（5%）。平均で毎分約8.7個
- 閉じている間：増えない
- 風船：最初は3分後、以後は4〜6分ごと。約30秒で横切る。プレゼントの中身は15個（40%）、25個（44%）、50個（16%）で平均25個
- 階の値段：2階120個、3階300個
- 雨：約40秒。ドラゴンは80%で外へ、ねこ、こいぬ、うさぎ、ひつじは15%で外に残る
- 家具：全23種、4〜30個、合計310個。各階の寝床（ねこ、こいぬ、うさぎ）は最初からある。ドラゴンは来るときに自分のいすを持ってくる
- おやつ：貝がらクッキー5個（なつき+1）、ラムネアイス12個（+2）。おもちゃ：ビーチボール8個（+2）、かざぐるま15個（+3）
- なつき度は0〜10で、ハートは2ごとに1つ。4と8で新しいしぐさを覚える
- 窓辺のおやつ：10個。次に開いたとき、ちびドラゴン、くものひつじ、ペンギンの順に1匹ずつ来る
- 空腹：満腹から0まで30分。30%以下で家にいる。クッキーで50%、ラムネアイスで100%回復
- 屋根の色：1回20個
- シーグラス：15秒拾わないと1個が強く光る

## 動物の居場所

左の柱に沿ったはしごで、階と地面と屋根をつなぐ。1階は正面からも外へ出られる。ひつじとドラゴンは飛んで出る。

- 家：1階 ねこ、くものひつじ／2階 こいぬ、ちびドラゴン／3階 うさぎ／桟橋 ペンギン
- 出かける先：屋根、やしの木、砂浜、桟橋の先、ひまわり畑、潮だまり、デッキチェア
- ヤシの葉は8枚が別々に、先端だけゆっくり揺れる。全体を距離で動かすと、1ピクセルずれる境目が円になって伸び縮みして見えるため
- ストーリー：カニにちょっかい（crab）、船を眺める（boat）、天気雨と虹（rainbow）、木登り（palm）、屋根（roof）、浜辺（beach）。室内だけの play、perch、snack、quiet も残す

## 暇な時間

ストーリーの空き時間（出だしの待ち時間と、終わったあとの残り）は、すべて `idle(T, r, 秒数)` で埋める。空き時間を寝床で寝て埋めていたのが、寝ている時間が半分になっていた原因だった（修正前は、ねこ50%、こいぬ49%、うさぎ57%）。

- `idle` は家で始まり、決めた時刻ちょうどに家で終わる。だから、決まった時刻に落ち合う場面はそのまま動く
- 中身は、家具やその階の空いた場所への往復（`trip`）と、家での小さなしぐさ（`fidget`）。往復が残り時間に収まるかは、捨てる `Track` で先に走らせて測る
- 行き先は `FURN_SPOT` の表で決める。`look` は眺める場所、`on` は乗る場所、`mid` は途中の足場、`far` は部屋の中心を通る印、`via` は個別の経路、`not` は使わないペット
- 眺める場所は家具より画面の下にする。ペットの眺める絵は奥を向いているので、家具を見上げているように見える
- 階の移動は `ROOMS` の `way`（部屋の入口からはしごの降り口まで）を、どの階でも同じ形で使う
- 同じブロックで同じ家具に同時に行かないよう、`ctx.visits` に時間帯を記録する
- 家具を買っても再生中のブロックは変えない

寝る場面は、rest と昼寝のストーリーに短く残し、家でのうたた寝を足す。うたた寝の起こりやすさと長さは `NAP` の表でペットごとに変え、割合の差を作る。奥の壁の棚の上は上の階の床に隠れるので乗らない。昼寝で落ち合う3匹の終わりは84秒から54秒に早める。空腹で家にいるときは、10〜16秒寝て6〜10秒起きるのを繰り返す。

## カメラ

`CAM` は階や全体の決まった枠のほかに、ペットを追う2つの状態を持つ。

- `close`：おやつとおもちゃ。90×160（4倍）。喜ぶ動きが終わると `camState` で覚えた元の状態へ戻る
- `follow`：「ついていく」。120×213（3倍）
- どちらも毎フレーム `petRect` で枠を計算し、絵の外に出ないよう収める。カードが開いているときは、カードに隠れないようペットを上から36%の高さに置く。閉じていれば中央
- 枠の大きさが落ち着いたら位置を整数に丸める。ペットが歩く間に絵がちらつかないようにするため
- 階や全体のボタンは `setView` を通るので、どちらの状態も解除する。購入の強調も `camState` を覚えて戻すので、追っている途中に買っても追跡に戻る

## チュートリアル

- 進み具合は `GS.tut`（`gift`、`fed`、`furn`）に持つ。`null` は終わった印で、古いセーブには項目がないので `null` になる
- 今の段階は `tutStep()` が状態から毎回計算する。カードやおみせを閉じたら自動で一つ前の案内に戻るので、遷移の管理がいらない
- 吹き出しと矢印は `pointer-events: none` で、下の操作を邪魔しない。押せるのはスキップと「はじめる」だけ
- 矢印の位置は毎フレーム、目標の要素の矩形から計算する。シーグラスは `SLOTS` の位置をカメラで変換する
- カメラが寄っている間、強調表示の間、確認画面やメニューが開いている間は隠す
- 自動テストは `notut=1` を付けて、案内とおまけなしで動かす

## 交流

各ストーリーに1組の交流を割り当てる。相手がいなければ、そのストーリーの一人の行動に戻る。

| ストーリー | 交流 | 組 |
|---|---|---|
| beach | 鼻をつけてあいさつ | ねこ、こいぬ |
| play | 追いかけっこ | ねこ、こいぬ |
| perch | 寄り添って昼寝（短く） | ねことうさぎ（いなければ、ねことこいぬ） |
| quiet | 寄り添って昼寝 | こいぬ、ひつじ |
| crab | ねこがこいぬを誘ってカニへ | ねこ、こいぬ |
| snack | 火を吹き、雨で消す | ドラゴン、ひつじ（いなければ、ねことこいぬのあいさつ） |
| boat、roof、rainbow、showcase | 並んで眺める | ねこ、こいぬ |
| palm | 木の上のねこに、こいぬがほえる | ねこ、こいぬ |

## 雨の日

rainbow と showcase が雨のストーリー。降り始める前に動物を外へ出しておき、雨で室内へ急ぐ様子が見えるようにする。

- 外で虹を眺める場所は、虹が塔に隠れないところ：桟橋の先、デッキチェア、屋根。塔の真正面と真後ろには行かない
- 自動テストで、多数のシードについて雨の間の居場所の割合と、虹を眺める場所を確かめる
